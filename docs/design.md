# 텔레그램 완성-확인-주소 전달 자동화 설계

> 2026-11-17 갱신: 실제 업무 흐름(예약 확정 → 완성 → 준비 확인 → 주소)에 맞춰 구현이 바뀌었습니다. 현재 동작은 README.md '3-1' 절이 기준입니다. 아래는 이전 설계 기록입니다.

작성일: 2026-11-17 (개정 2: 배정자 여럿·담당자 단톡방 반영)

## 등장인물
- **나 (배정자)**: 프로그램이 돌아가는 개인 텔레그램 계정. 관리는 '저장한 메시지'에서 명령으로 한다. 이 자동화는 나만 쓴다.
- **다른 배정자들**: 나와 같은 역할을 하는 사람들. 프로그램은 쓰지 않는다. 담당자의 단톡방에 같이 들어와 있다.
- **대상**: 1:1로 메시지를 보내는 누구든. 담당자를 요청하고, 나중에 완성 알림을 보낸다.
- **담당자**: 미리 등록된 사람. 이름(별칭 여러 개 가능), **본인과 배정자들이 함께 있는 단톡방**, 배송주소 텍스트를 가진다. 한 번에 대상 1명만 맡는다.

## 원칙: 담당자 가능 여부는 프로그램이 판단하지 않는다
다른 배정자들이 같은 담당자에게 배정하는 상황은 프로그램이 알 수 없다. 그래서 프로그램은 **알림과 참고 정보만** 준다. 담당자를 가능하다고 판단하고 확정하는 건 언제나 내가 한다.

## 흐름

```
① 대상A: "김담당으로 요청드려요"
   └ 건 #3 생성 (상태: 확정대기). 대상A에게는 자동 답장을 보내지 않는다.
   └ 나에게 알림:
        "🆕 #3 홍길동(@hong) → 김 요청
         참고(내 건 기준): 김 비어 있음 / 김은 #1 박영희 담당 중
         원문: '김담당으로 요청드려요'"
② 내가 단톡방 정보를 보고 판단한 뒤, 대상A와 직접 대화한다. (예: "김은 어렵고 박 가능한데 진행할까요?")
③ 확정: /확정 3 박
   └ #3 담당자 = 박 (상태: 완성대기). 대상A에게는 아무것도 보내지 않는다 (안내는 내가 직접).
   └ 박이 내 다른 건을 맡고 있으면 경고하고, /확정 3 박 강제 로만 진행한다.
④ 대상A: "…완성…"
   └ 박의 단톡방에 확인요청을 올린다:
        "[#3] 홍길동 님 완성 건 확인 부탁드립니다. 이 메시지에 '답장'으로 확인해 주세요."
   └ 상태: 확인대기. 나에게 "📨 #3 박 단톡방에 확인요청" 알림.
⑤ 박: 위 요청 메시지에 '답장'으로 "확인"
   └ 나에게 "✅ #3 박 확인" 알림
   └ 대상A에게 박의 배송주소 텍스트를 발송
   └ 단톡방 요청 메시지에 "#3 주소 전달 완료" 답장. 상태: 완료 → 박 풀림
```

## 단톡방 혼선 방지
- 단톡방의 확인은 **내가 올린 요청 메시지에 대한 답장(reply)**만 인정한다. 답장이 아닌 "확인"이나 다른 배정자가 올린 메시지에 대한 답장은 무시한다.
- 답장한 사람이 그 건의 담당자 본인일 때만 인정한다. 다른 배정자가 답장으로 "확인"을 보내면 무시하고 나에게 알린다.
- 요청 메시지에는 항상 `[#번호]`와 대상 이름을 넣어서, 다른 배정자들도 누구 건인지 알아볼 수 있게 한다.
- 단톡방에 프로그램이 보내는 건 확인요청과 완료 답장 두 가지뿐이다.

## 상태
`확정대기` → `완성대기` → `확인대기` → `완료`  (어느 단계에서든 `/취소` → `취소`)

## 예외 처리
- 확정되지 않은 대상이 '완성'을 보내면: 나에게 "#N 담당자 미확정, /확정 필요" 알림. 확정하는 즉시 확인요청을 올린다.
- 담당자 이름 없이 '완성'만 온 신규 대상: 건을 만들고(확정대기) 나에게 알린다.
- 진행 중인 건이 있는 대상이 다른 담당자 이름을 보내면: 나에게 "변경 요청" 알림만 보낸다. 바꾸려면 내가 /확정 으로 다시 확정한다.
- 이미 `완료`된 건에 다시 확인이 오면: 주소를 다시 보내지 않는다.
- 담당자가 요청 메시지에 "반려 사유"로 답장하면: 나에게 알리고 상태를 `완성대기`로 되돌린다.
- 데이터는 SQLite(`automation.db`)에 저장한다. 프로그램을 다시 켜도 진행 중인 건이 그대로 남는다.

## 저장한 메시지 명령어 (추가분)
| 명령 | 설명 |
|---|---|
| `/담당자추가 박, 박담당 \| 단톡방 링크 또는 이름 \| 주소 텍스트` | 별칭은 쉼표로 구분. 담당자 본인 계정은 단톡방 멤버 중에서 선택한다 |
| `/담당자목록` | 담당자별로 내 건 기준 비어 있음 / 담당 중 표시 |
| `/담당자수정 박 \| 주소 텍스트` · `/담당자삭제 박` | |
| `/확정 3 박` | 담당자 확정 또는 변경 (대상에게는 아무것도 보내지 않음) |
| `/대기` | 진행 중인 건과 단계 |
| `/취소 3` | 건 취소, 담당자 풀림 |
| `/재요청 3` | 단톡방에 확인요청을 다시 올림 |

기존 키워드 자동응답(`/추가` 등)과 '도착' 규칙은 그대로 유지한다.

## 코드 구조
- `store.py`: SQLite 저장소 (담당자, 건, 키워드 규칙)
- `workflow.py`: 상태 전이 로직. 텔레그램 없이 테스트할 수 있게 순수 함수로 만든다
- `commands.py`: 저장한 메시지 명령 파싱
- `main.py`: Telethon 연결과 메시지 라우팅 (1:1 / 단톡방 답장 / 저장한 메시지)
- `tests/`: workflow와 commands 단위 테스트

## 미정
- 운영 위치(PC / 폰 / 서버): Defender 검사 결과를 보고 정한다.
- '요청'과 '완성'을 알아보는 키워드: 기본값은 담당자 이름·별칭 포함 = 요청, "완성" 포함 = 완성. 명령어로 바꿀 수 있게 한다.
